# 코드반장

요청 하나를 던지면 AI 팀(PM·개발·QA)이 작업을 나누고, 실제로 내 프로젝트 코드를 고치고, 테스트로 검증한 뒤 **내가 승인해야만 반영되는** Windows 앱입니다. 팀이 쓴 비용과 시간, 실패 횟수를 전부 기록해서 "AI 팀이 정말 혼자보다 나은가"를 숫자로 확인하는 것이 목표입니다.

> 상태: **개발 중** — 화면 앱은 [app/](app/README.md)(작업공간·지식 문서·반영·작업 현황), 아래는 명령줄 도구입니다. 이름은 가칭 "AI Office"에서 "코드반장"으로 바꿨습니다.

## `aio-run` — 요청 하나를 팀에게 맡기기

```
aio-run -repo C:\aio-lab\textstats -check "go test ./..." -protect "*_test.go" ^
  -request "stats.go의 Count 함수를 구현해서 테스트가 통과하게 하고, 사용 예제가 들어간 README.md를 써줘."
```

1. **PM**이 저장소를 읽고 요청을 작업 1~5개로 나눕니다(파일은 고치지 않음).
2. **개발자**가 작업을 순서대로 수행합니다. 작업마다 앞 작업의 보고를 함께 받습니다.
3. **검사**: `-check`로 준 명령을 앱이 직접 실행합니다. `-protect`에 해당하는 파일(예: 테스트)을 AI가 바꿨으면 되돌리고 실패로 처리합니다.
4. 실패하면 실패 출력을 붙여 개발자에게 **수정 작업**을 다시 줍니다(`-fix-rounds`, 기본 3회).
5. 통과하면 결과를 요청 전용 브랜치에 커밋합니다. **원래 브랜치에는 합치지 않습니다.** 보고서 끝에 검토·반영·폐기 명령이 나옵니다.

`-budget`(요청 전체 최대 달러, 기본 2.0)을 다 쓰면 그 자리에서 멈춥니다. `-solo`를 주면 PM 없이 개발자 혼자 요청 전체를 수행합니다(팀과 비교용). 모든 단계, 상태 변화, 실행, 검사는 `aio.db`(SQLite)에 남고, 요청마다 `requests\<시각>\report.md`가 생성됩니다. 실행 도중 앱이 꺼지면 다음 실행 때 그 요청을 `INTERRUPTED`로 표시합니다.

### QA 리뷰어
검사가 통과한 뒤 **QA 리뷰어**(읽기 전용)가 변경 내용(diff)을 요청·명세와 비교합니다. 검사가 못 잡는 결함(요구사항 누락, 경계 조건 위반)을 찾으면 그 내용을 개발자에게 수정 작업으로 돌려보냅니다. 스타일 지적은 하지 않습니다. `-review=false`로 끌 수 있고 `-qa-model`로 모델을 따로 고를 수 있습니다.

## `aio-bench` — 같은 과제를 여러 번 돌려 비교하기

```
aio-bench -task demos\ledger -modes solo,team,review -models sonnet -n 3
```

- `solo`: 개발자 혼자 / `team`: PM + 개발자 + 검사 / `review`: team + QA 리뷰어
- 과제 폴더의 `task.json`에 요청, 검사 명령, 보호 파일, **채점 방법**을 적습니다. 채점용 테스트(`hidden/`)는 AI에게 보이지 않습니다. 팀이 끝난 뒤에만 작업 폴더에 복사해 실행하고 바로 지웁니다.
- 결과 표: 검사 통과 수, 숨김 테스트 통과 수, 비용·시간 중앙값, 평균 수정 횟수, 보호 파일을 건드린 횟수.

데모 과제:
- `demos/textstats` — 쉬움(함수 하나)
- `demos/ledger` — CSV 가계부 파서. 공개 테스트 4개는 기본만 확인하고, 숨김 테스트 8개는 명세(`SPEC.md`)의 경계 조건(따옴표 칸, 여러 줄 메모의 줄 번호, 금액 형식, 윤년 등)을 확인합니다. 숨김 테스트는 `reference/`의 참고 구현으로 모두 통과하는 것을 확인했습니다.

## `aio-probe` — 엔진 실험 도구

코딩 에이전트(현재 Claude Code)를 내 저장소의 **별도 작업 폴더(git worktree)와 별도 브랜치**에서 실행합니다. 무엇을 했는지, 토큰과 비용이 얼마나 들었는지, 어떤 파일이 바뀌었는지 보여 줍니다.

- 원래 작업 폴더와 브랜치는 건드리지 않습니다(실행 전후를 비교해서 확인).
- 에이전트는 작업 폴더 안의 파일만 읽고 쓸 수 있고, 셸 명령은 실행할 수 없습니다.
- 시간 제한이나 Ctrl+C로 멈추면 에이전트가 띄운 프로세스까지 모두 종료합니다(Windows Job Object).
- 끝난 뒤 내가 정한 검사 명령(빌드·테스트)을 실행해 통과 여부를 판정합니다. AI가 "완료했습니다"라고 말하는 것과 실제로 테스트가 통과하는 것은 다른 문제라서입니다.

### 필요한 것
- Windows 10/11, Go 1.22 이상, Git
- Claude Code 설치 및 로그인(`claude` 명령이 동작해야 함)

### 빌드와 실행
```
cd codebanjang
go build -o bin/ ./cmd/...

# 데모 프로젝트를 git 저장소로 복사
xcopy /E /I demos\textstats C:\aio-lab\textstats
cd C:\aio-lab\textstats && git init && git add -A && git commit -m start

aio-probe -repo C:\aio-lab\textstats -check "go test ./..." ^
  -prompt "stats.go의 Count 함수를 구현해서 테스트가 통과하게 해줘. 테스트 파일은 고치지 마."
```

주요 옵션: `-model`(기본 sonnet), `-timeout`(기본 10분), `-budget`(실행당 최대 달러, 기본 1.0), `-check`(검사 명령), `-cleanup`(끝나면 작업 폴더와 브랜치 삭제), `-data`(작업 폴더·기록 위치, 기본 `%LOCALAPPDATA%\codebanjang`).

실행 기록은 `runs\<시각>\`에 남습니다: 원본 이벤트(`stream.jsonl`), 변경 내용(`diff.patch`), 검사 출력(`check.txt`), 요약(`summary.json`).

비용은 API 표준 가격 기준 추정치입니다. 구독 요금제로 쓰는 경우 실제 청구액과 다릅니다.

## 앞으로
1. PM이 요청을 작업과 완료 조건으로 나누고, 개발 → QA 검증 → 재작업을 반복하는 흐름
2. 화면 앱(Wails), 승인 화면(변경 내용·요약·테스트 결과·비용)
3. 두 번째 엔진(Codex), 혼자 vs 팀 측정 비교
