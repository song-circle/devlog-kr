# 코드반장 화면 앱 (Wails v2 + Svelte 5)

명령줄 도구(`aio-run`)와 같은 오케스트레이터를 화면에서 씁니다.

- **시작 화면과 작업공간**(VS Code의 작업 폴더처럼): 실행하면 **폴더 열기**로 프로젝트 폴더(git 저장소)를 고릅니다. 처음 연 폴더는 자동으로 등록됩니다. **폴더 설정 → + 폴더 추가**로 여러 폴더를 한 작업공간에 묶을 수 있고, 요청 목록에는 그 작업공간 폴더들의 요청만 나옵니다. 최근 작업공간은 시작 화면에 남습니다.
  - **새 창**으로 창을 여러 개 띄워 창마다 다른 작업공간을 열 수 있습니다(창마다 별도 프로세스, `codebanjang.exe --workspace <번호>`). 직원과 AI 계정, 기록은 모든 창이 함께 씁니다.
  - 한 창에서 실행 중인 요청은 다른 창을 새로 열어도 중단 처리되지 않습니다(요청마다 실행한 프로세스를 기록하고, 그 프로세스가 끝났을 때만 `INTERRUPTED`).
- **작업 현황**(왼쪽 메뉴): git 클라이언트처럼 "지금 어디까지 됐나"를 한 화면에 보여 줍니다.
  - 위: 운영(origin/main) 마지막 반영·운영 대기 건수, 개발(origin/dev), 내 PC(체크아웃 브랜치·커밋 안 한 변경·dev보다 몇 건 뒤). "GitHub에서 새로고침"으로 원격 상태를 받습니다.
  - 가운데 보드: 작업 중 / 반영 대기 / 개발 반영됨 / 운영 반영됨 / 멈춤. "운영 반영됨"은 앱 기록이 아니라 그 요청의 커밋이 실제로 origin/main에 들어갔는지 git으로 확인합니다(GitHub에서 PR을 merge하면 옮겨짐). 카드를 누르면 요청 화면으로 갑니다.
  - 여러 사람: AI가 만드는 커밋에 요청 정보(트레일러 `Codebanjang-Request`·`Codebanjang-Requester`, 반영 때 `Codebanjang-Deployed-By`)를 넣습니다. 요청자 이름은 각자의 git `user.name`입니다. 그래서 서버 없이도 GitHub의 dev 이력만으로 **다른 사람 요청까지** "개발 반영됨/운영 반영됨"에 누가 요청했는지와 함께 나옵니다. 작업 중·반영 대기·멈춤은 아직 push 전이라 각자 PC에서만 보입니다.
  - 아래 이력 그래프: main·dev·요청 브랜치를 선으로 그립니다. AI가 만든 커밋(🤖)은 누르면 그 요청으로 갑니다. 사람이 직접 올린 커밋도 함께 보입니다.
- **반영(개발·운영 브랜치)**(폴더 설정 → 설정 → 개발 브랜치 `dev`, 운영 브랜치 `main`): 여러 사람이 같은 GitHub 저장소를 고칠 때 씁니다.
  - 코드 수정 요청은 이 PC에 체크아웃된 브랜치가 아니라 **GitHub(origin)의 최신 개발 브랜치**에서 시작합니다.
  - 검증을 통과한 요청의 **개발(origin/dev)에 반영**(누구나): 그사이 다른 사람이 반영한 최신 dev를 합치고 → 준비 명령(새 코드가 들어왔을 때)과 검사를 **합친 코드에서 다시** 돌리고 → 통과하면 push합니다. 강제 push는 하지 않습니다. 충돌하거나 검사가 실패하면 반영하지 않고 이유를 보여 줍니다. 검사 도중 누가 또 push했으면 다시 합쳐서 검사합니다(최대 3번).
  - **운영 반영 요청**(폴더 카드의 버튼): 운영 브랜치에는 앱이 절대 push하지 않습니다. GitHub CLI(`gh`, 각자 `gh auth login`)로 dev → main PR을 만들고(이미 열려 있으면 그것을) 브라우저로 엽니다. 본문에는 아직 운영에 없는 커밋 목록이 들어갑니다. 승인과 merge는 GitHub에서 합니다 — 운영 브랜치 보호 규칙(승인 필수)은 GitHub 저장소 설정에서 켜 두세요.
  - 개발 브랜치를 비워 두면 예전처럼 이 PC 저장소의 현재 브랜치에 바로 merge합니다.
- **작업 폴더 준비**(폴더 설정 → 설정): AI는 요청마다 git에 있는 파일만 든 별도 작업 폴더에서 일하므로, `.env`·설치된 패키지처럼 git에 없는 파일이 빠져 빌드·검사가 실패할 수 있습니다. 코드 수정 요청에서 AI가 일을 시작하기 전에:
  - **복사할 파일·폴더**: 프로젝트 폴더에서 작업 폴더로 복사합니다. git이 무시하는(.gitignore에 있는) 파일만 받습니다 — 그렇지 않으면 AI의 변경 내용과 커밋에 섞이기 때문입니다. 없는 파일은 건너뜁니다.
  - **준비 명령**(`npm ci`, 코드 생성 등): 차례로 실행합니다(각 15분 제한). 실패하거나 git에 잡히는 파일을 만들거나 바꾸면 요청을 멈춥니다.
  - 요청 화면 단계 표에 "준비" 줄로 결과가 남습니다. 복사한 파일은 AI도 읽을 수 있습니다.
- **프로젝트 지식 문서**(폴더 설정 → 지식 문서): 모든 직원이 일을 시작하기 전에 읽는 문서입니다(구조, 실행 방법, 화면·기능 → 코드 지도, 용어, 위험 영역, 모르는 것). 저장소 안 `.aioffice/knowledge.md`에 저장되어 git으로 함께 넘어가고, 사람에게는 인수인계 문서가 됩니다.
  - **파악 시작 / 다시 파악**: 직원 한 명이 저장소를 읽기만 해서 초안을 씁니다(지금 문서가 있으면 코드에 맞게 고친 판). 초안은 요청 화면에 나오고, **검토하고 지식 문서로 저장**을 눌러 고친 뒤 저장해야 파일이 바뀝니다.
  - `## 사람이 적은 내용` 칸은 AI가 다시 써도 앱이 그대로 옮겨 붙입니다(코드에서 보장).
  - 코드 수정 요청에서 AI는 이 문서를 고칠 수 없습니다(보호 파일에 자동 추가). 지시에는 앞 3만 자까지 들어갑니다.
  - 저장만 하고 커밋은 하지 않습니다. 화면에 git 상태(아직 git에 없음 / 바뀜)가 나옵니다.
- **직원 관리**: 직원마다 이름, 역할(PM / 개발자 / QA), 모델, 추가 지시, AI 계정 연결을 정합니다.
  - *이 PC 기본 로그인*: 지금 PC의 Claude Code에 로그인된 계정을 그대로 씁니다.
  - *전용 계정(구독 / Console)*: 직원마다 별도의 Claude Code 설정 폴더(`%LOCALAPPDATA%i-office\profiles\employee-N`)를 두고, **[로그인]**을 누르면 Claude Code의 공식 `claude auth login`이 브라우저 로그인을 엽니다. 로그인·콜백·자격 증명은 Claude Code가 처리하고 앱은 계정 정보를 저장하지 않습니다. 브라우저가 안 열리면 화면에 나오는 링크나 코드 붙여넣기로 마칠 수 있습니다.
  - 구독 로그인은 본인 PC에서 본인이 쓰는 용도로만 쓰세요. 다른 사람에게 배포하는 용도라면 Console(API 과금)을 쓰는 것이 Anthropic 정책에 맞습니다.
- **폴더 설정**: 작업공간의 폴더마다 이름, 검사 명령, 보호 파일, 프로젝트 설명(기술 스택·규칙·배경)을 정합니다. 프로젝트 설명은 모든 직원의 지시에 자동으로 붙습니다.
- **새 요청**: 작업공간의 폴더 중 하나를 고르고 요청을 적은 뒤 진행 방식과 참여 직원을 고릅니다.
  - 모든 진행 방식에서 직원의 지시에 프로젝트 지식 문서와 프로젝트 설명이 붙습니다.
  - 읽기만(프로젝트 파일을 바꾸지 않고, 브랜치도 만들지 않음): **질문하기**(아무 직원) / **기획만**(PM이 기획서 작성) / **검토만**(QA가 지금 코드의 결함 보고)
  - 코드 수정(별도 브랜치, 승인해야 반영): **혼자 개발** / **팀**(PM + 개발자 + 검사) / **팀 + QA 리뷰**
- **요청 화면**: 단계별 표(담당·상태·비용·시간), 실시간 진행 기록, 변경 내용(diff), 보고서
- **이어서 시키기**(요청 화면): AI가 질문하고 멈췄을 때(NO_CHANGE — 파일을 하나도 안 바꿈) 답을 적으면, 또는 결과(DONE)를 반영 전에 더 고치고 싶을 때, 실패·중지된 요청에 방향을 알려 줄 때 **같은 작업 폴더·브랜치에서** 개발자가 이어서 하고 검사를 다시 돌립니다. AI의 마지막 말(질문·보고)이 위에 나옵니다. "이번에는 보호 파일도 고쳐도 됨"을 켜면 그 한 번만 보호 파일 수정을 허용합니다(지식 문서는 계속 보호). 추가 예산을 따로 정합니다. 답은 단계 표와 커밋 메시지("이어서 한 지시")에 남습니다.
- **승인하고 반영**: 검증을 통과한 요청만. 요청 브랜치를 원래 저장소의 현재 브랜치에 merge합니다(충돌이 나면 되돌리고 알림).
- **폐기**: 작업 폴더와 브랜치를 지웁니다.
- **중지**: 실행 중인 AI 프로세스를 모두 종료합니다.

기록은 `%LOCALAPPDATA%\codebanjang\aio.db`(가칭 시절에 쓰던 PC는 `ai-office` 폴더를 그대로 씀)에 남고, 실행하던 창(프로세스)이 꺼져서 끝나지 못한 요청은 다음 실행 때 `INTERRUPTED`로 표시됩니다.

## 빌드
```
go install github.com/wailsapp/wails/v2/cmd/wails@v2.17.1
cd codebanjang\app
wails build        # build\bin\codebanjang.exe
```
